# 2026-11-02 M6 收尾：LangSmith 追踪 + Docker 一键部署

## 一、LangSmith 全链路追踪（已完成）

- 新增 `app/observability/tracing.py`：`trace_request`（根 span）/ `trace_generation`（llm span）/ `record_output`。
  未配置 key 或 `LANGSMITH_TRACING=false` 时全部透传，零网络请求。
- 配置项：`LANGSMITH_TRACING` / `LANGSMITH_API_KEY` / `LANGSMITH_PROJECT` / `LANGSMITH_ENDPOINT`。
- 一次问答一条 trace，实测 8 个 span：
  `AgentService.answer` → `LangGraph` → `router` → `_route_after_router` → `retrieve` → `grade` → `_route_after_grader` → `generate`。
- **四个踩坑（都是实测才发现的）**：
  1. 节点 span 不能手动埋点：LangGraph 在追踪开启时已原生上报节点名，再加一层会出现同名 span 重复。
  2. 载荷必须脱敏：原生节点输出是整个 `AgentState`（含 50 条候选正文）。客户端挂 `hide_inputs` / `hide_outputs`
     把候选压成 `{id, score}`，单 trace 输出从几十 KB 降到约 1.8 KB。
     **注意节点里放的是 `SearchResult` 对象而非 dict**，脱敏函数只判断 dict 会把候选清空（看起来像检索为空）。
  3. 嵌套 `tracing_context` 会把父 run tree 重置为 None，导致 `generate` 变成独立 trace——只在根开一次上下文。
  4. **SSE 端点必须是 async**：同步生成器被 Starlette 丢线程池迭代，`with` 进入/退出跨线程，根 span 上报不出去
     （表现为只剩一个孤立 `generate`）。改 async 端点 + `run_in_threadpool` 隔离阻塞检索/打分。
- 测试隔离：`tests/conftest.py` 强制 `os.environ["LANGSMITH_TRACING"]="false"`（env 优先于 .env），
  否则开发者本地开追踪后单测会往远端刷几百条 trace。
